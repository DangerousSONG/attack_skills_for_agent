# RFC 审计规则 Skill 模板（SKILL_TEMPLATE.md）

每个 RFC 审计规则 Skill 一个目录，目录名建议 `rfc<编号>-<约束主题slug>`（如 `rfc9114-capsule-no-content-length`）。
目录内一个 `SKILL.md`，**只放判定规则与导航，不放攻击代码**——攻击动作由技能层 Skill + 工具层工具完成。

## SKILL.md 固定六字段

```markdown
---
name: rfc9114-capsule-no-content-length
description: 审计 HTTP/3 目标是否违反 RFC 9114 §4.2 约束——使用 capsule protocol 时请求不得同时携带 Content-Length；命中即存在请求走私攻击面
license: Apache-2.0
---

# RFC 9114 capsule protocol 与 Content-Length 互斥约束审计

## 1. 约束条款（原文出处）
> RFC 9114 §4.2：<约束原文引用>

## 2. 违规判定条件
- 可程序化判定的条件清单（请求特征 / 响应特征 / 行为特征）
- 每条给出判定方法（单包探测 / 差分对比 / 日志观察）

## 3. 攻击面猜想
- 违规点可能导致的漏洞类型（如：请求走私 → 缓存投毒 / 会话劫持 / 访问被拦截后端）

## 4. 关联历史 CVE
- 同约束 / 同模式的已公开漏洞（CVE 编号 + 受影响实现 + 根因一句话）

## 5. 差分验证方法
- 选哪些开源实现做差分对照、对比什么字段、误报如何排除

## 6. 对接的攻击 Skill
- 命中后应加载的技能层 Skill slug（方法论）与工具层工具（执行）
```

## 填写质量要求

- **判定条件必须可执行**：Agent 读完应能写出探测脚本，不允许"可能存在风险"式模糊表述
- **每条约束一个 Skill**：跨约束的聚合分析交给 Router 层组合调度，不在单条内展开
- **CVE 关联必须有根因对齐**：不是"同协议的其他漏洞"凑数，而是触发条件同模式
- **引用合规**：约束原文按 IETF Trust License 合理引用范围摘录，标注章节号

## 已验证样例（来自分享会实证）

| 约束 | 猜想 | 战果 |
|---|---|---|
| RFC 9114 §4.2 capsule 不得与 Content-Length 共存 | 前后端解析差异 → 请求走私 | 某流行 HTTP/3 代理产品确认漏洞（未公开） |
| RFC 9114 QPACK 动态表条目上限约束（同模式历史 CVE） | 伪造帧反复申请大内存 → 服务端内存耗尽 | QUIC-Go 同类漏洞，已修复 |
